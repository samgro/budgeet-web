Design system

Tailwind v4, CSS-first, no config file. Everything here is a token in globals.css or a component in ui.tsx. The product is a ledger you scan quickly and correct occasionally, so the system is built for dense rows of numbers first and forms second.

Colour

Three groups. Surfaces and ink carry the whole interface; gold, green and red are reserved for state and never used decoratively. Gold in particular is a stroke, a tint or a word — put it on a button fill and it stops meaning anything. Tailwind's own palette is wiped in the theme block, so bg-blue-500 doesn't compile: if a colour isn't here, it isn't in the product.

One family, the system stack, so the app inherits whatever the OS thinks a readable interface is. Roles come from size, weight and ink rather than a second face. Body is 14px, not 16 — this is a table-shaped app and 16 pushes a row past comfortable scanning height.

Space and shape

Tailwind's 4px scale, used at six steps and no others. Picking from a short list is what keeps a solo project consistent six months in.

gap-14 — inside a pill, icon to its label
gap-28 — between controls in a group
gap-312 — between cells in a row
gap-416 — between fields in a form, row padding
gap-624 — between blocks, page padding on desktop
gap-1040 — between sections of a page

Radius follows size

4 6 8 12 16

Inline fields 4, menu items and small buttons 6, inputs and buttons 8, menus and cards 12, dialogs 16. Pills are always full.

Two shadows, or none

pop modal

Only things that actually float get a shadow. Everything resting on the page uses a hairline border instead — a card with both is a card doing too much.

Control heights

20 tag 24 budget pill 28 small button 32 menu item 36 button and input 44 transaction row

Six heights, and the row is 44 because that's the touch minimum. Anything smaller than 44 is pointer-only and must have a larger tap target on phones.

Buttons

Four intents, two sizes. Primary is ink, not gold — a gold button would make every screen look like it's warning you about something. Labels say what happens: Save changes, never Submit.

primary — the one committing action on a screen. Never two.

secondary — everything reversible. The default.

ghost — actions inside a row or toolbar, where a border would add a line to an already ruled surface.

danger — deletes only, and only after a confirm.

Inputs

Focus is a gold border plus a soft gold halo, which stays inside the element's box — the global outline would clip against a table cell. Labels sit above at 12px; there are no floating labels and no placeholders standing in for labels.

What to install, and what not to

A hobby project's real cost isn't bundle size, it's the day a dependency breaks and you have to relearn its API to fix your own app. Everything below is judged on that.

Install
tailwindcss

v4. No tailwind.config.ts — delete it if the scaffold made one.

clsx + tailwind-merge

The cn() helper. Two tiny packages that let a caller override a component's classes without a specificity fight.

lucide-react

Tree-shaken, one consistent stroke weight, no icon-font nonsense. Set it at 16px and leave it alone.

cmdk

The budget and tag pickers need filter-as-you-type with keyboard nav. This is the one screen where hand-rolling is a genuine mistake — you'd be reimplementing a combobox, and combobox accessibility is deceptively hard.

@radix-ui/react-popover

Only to anchor that picker. CSS anchor positioning still isn't safe across browsers, so this earns its place — for now.

Use the platform instead
<dialog>

Focus trap, Esc, inert background and a styleable backdrop, all free. Replaces a modal library outright.

<select>

For any short fixed list. The phone's native picker beats anything you'd build.

<input type="date">

Instead of a date-picker package, which is usually the largest thing in a finance app's bundle.

Intl.NumberFormat

Currency and date formatting. No dayjs, no currency.js.

CSS transitions

Two durations, 100ms for hover and press, 160ms for something appearing. No animation library.

Skip
shadcn/ui

Tempting, and it would work. But it lands forty files you now own and a colour system you didn't choose — and you already have a palette. Copy the two or three primitives you want if you want them.

class-variance-authority

A plain object keyed by variant name does the same job in four lines. See ui.tsx.

react-hook-form + zod

The forms here are four fields with no cross-field rules. Uncontrolled inputs and FormData are enough. Revisit if a form ever grows past ten fields.

a charting library

The widget's spend line is already hand-drawn SVG and reads better than a chart library's default. Keep drawing paths.

a state manager

Server components plus useState covers this. If refetch-after-mutate gets tedious, add SWR — but not before it does.

Rules worth keeping

The short list that stops this drifting. Everything else is negotiable.

  1. Gold never fills a button. It is focus, low confidence, and past pace — three states that all mean look here.
  2. Colour never carries meaning alone. Every state has a word, an icon, or a position saying the same thing.
  3. One primary button per screen. If two things look equally committing, neither is.
  4. A surface gets a border or a shadow, not both.
  5. Provenance shows in the detail view, never in the row. Whether a value came from the bank, from Claude, or from you is a question you ask once, deliberately.
  6. Nothing animates that the person didn't cause.
  7. Type sizes come from the scale; spacing comes from the six steps. Arbitrary values in a class name are a signal the system is missing something — add it to the theme instead.
